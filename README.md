# 🛒 SafeBasket

**Check the reviews before you check out.** SafeBasket analyzes the reviews of an e-commerce product and turns them into a trust score, a fake-review risk estimate, and a clear *Buy / Maybe / Don't Buy* recommendation.

Paste a product link from Amazon, Flipkart, Myntra and other supported stores, and SafeBasket tells you whether the ratings can be trusted, what buyers actually complain about, and whether a safer alternative exists.

---

## ✨ Features

| Area | What it does |
|---|---|
| **Trust Score (0–100)** | Combines average rating with fake-review risk, complaint rate and sentiment, then classifies the product as *Excellent / Good / Fair / Poor / Very Poor* |
| **Fake Review Detection** | Flags suspicious reviews using filler-phrase, text-length, punctuation, rating-spike and near-duplicate similarity signals |
| **Grievance Detection** | Surfaces the most common complaints, with a detailed breakdown by issue |
| **Sentiment Analysis** | VADER-based positive / neutral / negative split |
| **Game-Theory Decision Engine** | Weighs information reliability, value, and risk to return **Buy**, **Maybe** or **Don't Buy** |
| **Manipulation & Market-Risk Detection** | Detects review bursts, rating spikes, sentiment/rating mismatch, repetitive wording and timing patterns |
| **AI Purchase Advisor + Confidence Metrics** | Final recommendation with a confidence level, so you know how much to trust the verdict |
| **LLM Review Summary** | Pros, cons, warnings and verdict generated by an LLM (optional, with rule-based fallback) |
| **Smart Recommendations** | Similar products when the item is good, safer alternatives when it is risky |
| **Price Comparison** | Compares listings for the same product across sellers |
| **Product Compare** | Side-by-side analysis of two products |
| **Dashboard & History** | Per-user analysis history, purchase tracking and stats |

**Supported stores:** Amazon (`.in`, `.com`, `.co.uk`, `.de`, `.ca`, `.com.au`), Flipkart, Myntra, Snapdeal, Meesho, Nykaa, Ajio.

## 🧠 How it works

```
Product URL
    │
    ▼
Review extraction (SerpAPI) ──► Sentiment (VADER)
                           ├──► Grievance detection
                           └──► Fake-review detection
                                      │
                                      ▼
                              Trust score engine
                                      │
                                      ▼
                          Game-theory decision engine
                                      │
                                      ▼
   Rating distribution · Fake-review heatmap · Purchase behavior
   Market risk · Manipulation detection · Confidence · AI advisor
   LLM summary · Recommendations
                                      │
                                      ▼
                               JSON → React UI
```

### Trust score

1. **Base score** = `(average_rating / 5) × 100`
2. **Adjustments**
   - Fake-review risk: > 70 → −20, > 50 → −12, > 30 → −5
   - Complaint rate: > 50% → −15, > 30% → −8
   - Sentiment: > 80% positive → +5, > 50% negative → −10
3. **Clamp** to 0–100 and classify: ≥ 85 Excellent · ≥ 75 Good · ≥ 60 Fair · ≥ 45 Poor · else Very Poor
4. **Guardrails:** a product with red flags can't be rated Excellent or Good, and low average ratings cap the classification.

## 🧱 Tech stack

- **Backend:** Python, Flask, Flask-SQLAlchemy (SQLite by default, PostgreSQL via `DATABASE_URL`), Flask-CORS, Flask-Limiter
- **Auth:** JWT (PyJWT) with bcrypt password hashing
- **NLP:** VADER, TextBlob
- **Data providers:** SerpAPI (reviews), ScrapingDog / SerpAPI fallback (prices), optional ScraperAPI / Oxylabs / Bright Data
- **LLM:** OpenAI (`OPENAI_MODEL`, default `gpt-4o-mini`), optional
- **Frontend:** single-file React 18 app (`frontend/safebasket4.html`) loaded via CDN

## 🚀 Getting started

### Prerequisites

- Python 3.10+
- Node.js (only for `npx serve`; any static file server works)
- A [SerpAPI](https://serpapi.com) key (required for fetching real reviews)

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
python -m textblob.download_corpora

touch .env                      # then fill in your keys (see Configuration below)
python app1.py
```

The API runs on **http://localhost:5000**. Check it with `GET /`.

### 2. Frontend

```bash
cd frontend
npx serve .
```

Open **http://localhost:3000/safebasket4.html**.
The API address is set by `const API` near the top of the script in `safebasket4.html`; change it if your backend runs elsewhere.

### 3. First use

1. Click **Create Account** and register.
2. Open **Analyze** and paste a product URL.
3. Review the trust score, risk breakdown and recommendation.

## ⚙️ Configuration

Create `backend/.env`:

```env
# Core
SECRET_KEY=change-me
JWT_SECRET_KEY=change-me-too
FLASK_DEBUG=false
DATABASE_URL=sqlite:///safebasket.db
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
RATE_LIMIT=30 per minute

# Reviews and prices
SERPAPI_KEY=
SCRAPINGDOG_KEY=
MAX_REVIEWS=100
MIN_REVIEWS=1

# Optional scraping providers
SCRAPERAPI_KEY=
USE_SCRAPERAPI=false
OXYLABS_USER=
OXYLABS_PASS=
BRIGHTDATA_TOKEN=

# Optional LLM features (falls back to rule-based output if unset)
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini

# Optional Kaggle datasets for recommendations / purchase-behavior analysis
KAGGLE_USERNAME=
KAGGLE_KEY=
KAGGLE_DATA_DIR=/tmp/kaggle_data
```

> ⚠️ Never commit `.env`. Use long random values for `SECRET_KEY` and `JWT_SECRET_KEY`.

## 🔌 API reference

All responses use `{"status": "success" | "error", ...}`. Endpoints marked 🔒 need an `Authorization: Bearer <token>` header from `/login`.

| Method | Endpoint | Auth | Rate limit | Description |
|---|---|---|---|---|
| GET | `/` | – | default | Health check and feature list |
| POST | `/register` | – | 5/hour | Create an account |
| POST | `/login` | – | 10/hour | Log in and receive a JWT |
| GET | `/me` | 🔒 | default | Current user |
| POST | `/analyze` | 🔒 | 10/min | Full product analysis (`{"product_url": "..."}`) |
| POST | `/price-comparison` | 🔒 | 10/min | Compare prices across sellers |
| POST | `/compare` | 🔒 | 5/min | Compare two products |
| GET | `/history` | 🔒 | default | Past analyses |
| POST | `/purchase` | 🔒 | default | Record a purchase |
| GET | `/purchases` | 🔒 | default | Purchase history |
| GET | `/dashboard` | 🔒 | default | Stats, recent analyses and purchases |
| GET | `/stats` | 🔒 | default | Summary counts and average trust score |

The default limit is 100 requests per hour per IP.

**Example**

```bash
TOKEN=$(curl -s -X POST localhost:5000/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"********"}' | jq -r '.data.token')

curl -X POST localhost:5000/analyze \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"product_url":"https://www.amazon.in/dp/XXXXXXXXXX"}'
```

## ⚠️ Limitations

- Fake-review detection is **heuristic**, not a trained classifier. Treat it as a risk signal, not proof.
- Results depend on how many reviews the data provider returns; low review counts reduce confidence.
- Third-party scraping and review APIs are subject to their own terms, quotas and cost.
